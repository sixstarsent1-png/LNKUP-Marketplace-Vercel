# Vendor Experience 2.0 — Audit Matrix

Scope: vendor role on the WordPress plugin `lnkup-marketplace` + theme `lnkup-theme`, and the native Expo app `lnk-up-marketplace-mobile` (bundle `com.lnkup.marketplace`, fully native, no WebViews; hosted checkout opens in a system auth session).

Verification legend:

- **Verified (prod, read-only)** — reproduced with an anonymous, read-only request against `https://thelnkup.com` (counts only, no record bodies read).
- **Verified (static)** — confirmed by reading the code path end to end; not exercised at runtime.
- **Unverified** — suspected from code; needs a runtime run on staging / `localhost:8888` (no local WordPress was available while this matrix was written).
- **Fixed (pending runtime)** — code change landed; regression test written in `tests/e2e/vendor-security.spec.ts` but not yet run against a WordPress instance.

## Runtime verification (wp-env, Organizer 2.0 Sprint 0)

Local `@wordpress/env` on `http://localhost:8888`, seeded by `scripts/e2e/seed.php`; real `php -l` on all 280 plugin/theme files passes.

- `vendor-security.spec.ts` + `vendor-journey.spec.ts`: **32 passed, 2 skipped** (`sim_` check skipped because local simulation is enabled; foreign Stripe intent needs real test keys).
- Confirmed at runtime: A1 (`wp/v2/lnkup_*` → `rest_no_route`), B6 (approved $0 booth → payment `paid`, total `0`), C2 (3 parallel applies → one application), E1 server bounce, F1/F2/F3/F6/F7/F12/F13/G1.
- Bugs found and fixed during the run:
  - `LNKup_Checkout::prepare` created a simulated intent for an already-paid payment → now returns `no_payment_due`.
  - Login/signup `redirect=` values were not URL-encoded (`add_query_arg` does not encode), so `?view=payments&fin_tab=receipts` lost `fin_tab` after login — fixed in `lnkup_login_url_for`, `lnkup_registration_url_with_return`, apply modal, organizer follow, referral share, registration form.
  - Apply booth switch could overwrite `document.body` text ("Applied") when the modal was opened from `?apply=` — trigger element now limited to links/buttons.
  - Vendor Home welcome dropped the shared `.lnkup-page-header` markup (`dashboard-consistency`) — restored.
- Still not verified: E1 on a real device; B1/B2 with live Stripe test keys.
